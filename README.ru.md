## 1. Обзор

**Cert Unifier** (v2.9.0) — высокопроизводительный модуль на Bash, предназначенный для автоматизации сборки, проверки и унификации сертификатов SSL/TLS и закрытых ключей в стандартизованные пакеты PEM и PFX. Созданный для рабочих процессов DevOps и автоматизированного развёртывания веб-серверов (Nginx, Apache, HAProxy), он обеспечивает криптографическую согласованность и атомарность файловых операций при разнообразных структурах сертификатов.

### Назначение
Модуль упрощает управление жизненным циклом сертификатов за счёт:
- объединения конечных сертификатов и промежуточных цепочек с соответствующими закрытыми ключами
- проверки совпадения модулей RSA/EC, чтобы не развернуть несовпадающие файлы
- автоматического создания PKCS#12 (PFX) для сред Windows/IIS
- назначения безопасных прав на файлы (0600) для чувствительного криптографического материала
- поддержки как современных раскладок Certbot, так и устаревших структур каталогов

## 2. Ключевые возможности

### 2.1 Сборка единого PEM
- **Атомарная запись**: использует временные буферы, чтобы обеспечить целостность файла при сборке
- **Нормализация переводов строк**: гарантирует правильное разделение ключа и компонентов цепочки
- **Автообнаружение**: интеллектуальное сканирование устаревших и современных раскладок Certbot

### 2.2 Расширенная криптографическая проверка
- **Проверка модуля**: глубокая проверка закрытых ключей на соответствие сертификатам перед объединением
- **Целостность ключа**: поддержка нескольких движков (RSA/EC) для извлечения и сравнения модуля
- **Сопоставление PFX**: в v2.9.0 появилось автообнаружение подходящих пар ключ/сертификат для создания PKCS#12

### 2.3 Полная поддержка раскладок
- **Certbot изначально**: нативная обработка структур `/etc/letsencrypt/live`
- **Поддержка устаревших вариантов**: поддержка соглашений об именах `leX.crt` и `leX.key`
- **Фильтрация по TLD**: настраиваемая обработка доменов по доменам верхнего уровня (по умолчанию: .ru, .com)

### 2.4 Возможности корпоративного развёртывания
- **Режим сухого прогона**: полная проверка входных данных и выходных путей без изменения файловой системы
- **Безопасные права**: автоматическое назначение прав 0600 закрытым ключам и файлам PFX
- **Архитектура журналирования**: многоуровневое журналирование (DEBUG, INFO, WARN, ERROR) с метками времени

## 3. Системные требования

### 3.1 Минимальные требования
- **ОС**: Linux (любой современный дистрибутив), macOS или WSL
- **Оболочка**: Bash 4.0 или новее
- **Утилиты**: `openssl`, `grep`, `awk`, `date`
- **Права**: доступ на чтение исходных сертификатов; доступ на запись в выходные каталоги

### 3.2 Рекомендуемая конфигурация
- **OpenSSL**: 1.1.1+ (поддерживает современные ECC и атрибуты friendly name)
- **Файловая система**: поддерживается стандартная модель прав Linux/Unix
- **Зависимости**: полный набор инструментов `openssl` для создания PFX и глубокой проверки ключей

## 4. Быстрый старт

### 4.1 Развёртывание в 3 шага

**Шаг 1: Загрузка скрипта**
```bash
wget https://raw.githubusercontent.com/paulmann/cert-unifier/main/cert-unifier.sh
chmod +x cert-unifier.sh
```

**Шаг 2: Базовая унификация**
```bash
./cert-unifier.sh /var/www/httpd-cert
```

**Шаг 3: Расширенное создание PFX**
```bash
./cert-unifier.sh --pfx --pfx-password "your_password" /etc/letsencrypt/live
```

## 5. Установка и настройка

### 5.1 Установка вручную
1. Переместите скрипт в каталог из системного PATH (например, `/usr/local/bin`)
2. Убедитесь, что зависимости установлены: `apt install openssl grep awk`
3. При необходимости настройте переменные окружения:
   - `ALLOWEDTLDS="ru com org"`
   - `LOGLEVEL="INFO"`

### 5.2 Автоматизированная настройка CI/CD
В корпоративных средах подключайте скрипт через GitLab CI или GitHub Actions:
```yaml
- name: Unify Certificates
  run: |
    export ALLOWEDTLDS="com net"
    ./cert-unifier.sh --no-key-validation --output-dir ./dist /certs/source
```

## 6. Архитектура и компоненты

### 6.1 Поток логики
1. **Проверка окружения**: проверяет версию OpenSSL и зависимости
2. **Сканирование каталогов**: перебирает целевой корень, определяя раскладки
3. **Проверка**: извлекает модули; сравнивает пары ключ-сертификат
4. **Сборка**: Concat(key, chain) -> атомарная запись в .pem
5. **Создание PFX** (необязательно): преобразует пакет PEM в PKCS#12

***

## 7. Примеры использования

```bash
# Dry run with verbose debugging
./cert-unifier.sh --dry-run --verbose /etc/letsencrypt/live

# Process all domains (no TLD filtering)
./cert-unifier.sh --no-tld-filter /var/www/certs

# Generate PFX files and skip mismatches
./cert-unifier.sh --pfx --skip-pfx-on-mismatch /opt/certs

# Override output directory
./cert-unifier.sh -o /tmp/unified_certs /var/www/certs
```

## 8. Справочник параметров

| Параметр | Описание | По умолчанию |
| :--- | :--- | :--- |
| `-d, --dry-run` | Проверка без записи файлов | `false` |
| `-v, --verbose` | Включить журналирование уровня DEBUG | `false` |
| `-t, --tlds` | Список разрешённых TLD | `ru com` |
| `-o, --output-dir` | Переопределить выходной путь | Входной каталог |
| `--no-tld-filter` | Обрабатывать все домены | `false` |
| `--pfx` | Создавать файлы PKCS12 | `false` |
| `--pfx-password`| Задать пароль PFX | Пусто |

## 9. Технические замечания

### 9.1 Интеграция с OpenSSL
Скрипт определяет возможности версии OpenSSL во время выполнения. Поддержка PFX `friendlyname` автоматически включается для OpenSSL 1.1.x и 3.x, что обеспечивает лучшее отображение в диспетчере сертификатов Windows.

### 9.2 Механизм атомарной записи
Чтобы исключить состояния гонки, при которых веб-сервер может прочитать частично записанный сертификат, **Cert Unifier** пишет в `*.pem.new` и выполняет атомарное перемещение/переименование после успешной проверки.
