## 1. अवलोकन

**Cert Unifier** (v2.9.0) एक उच्च-प्रदर्शन Bash मॉड्यूल है, जो SSL/TLS प्रमाणपत्रों और निजी कुंजियों को मानकीकृत PEM और PFX बंडलों में संयोजित, सत्यापित और एकीकृत करने का कार्य स्वचालित करता है। DevOps वर्कफ़्लो और स्वचालित वेब सर्वर परिनियोजन (Nginx, Apache, HAProxy) के लिए बनाया गया, यह विविध प्रमाणपत्र संरचनाओं पर क्रिप्टोग्राफ़िक संगति और अटॉमिक फ़ाइल संचालन सुनिश्चित करता है।

### मुख्य उद्देश्य
मॉड्यूल प्रमाणपत्र जीवन-चक्र प्रबंधन को सरल बनाता है:
- लीफ़ प्रमाणपत्रों और मिलान करने वाली निजी कुंजियों के साथ इंटरमीडिएट चेन का विलय
- असंगत संपत्तियों के परिनियोजन को रोकने के लिए RSA/EC मॉड्युलस का मिलान सत्यापित करना
- Windows/IIS वातावरण के लिए PKCS#12 (PFX) निर्माण को स्वचालित करना
- संवेदनशील क्रिप्टोग्राफ़िक सामग्री पर सुरक्षित फ़ाइल अनुमतियाँ (0600) लागू करना
- आधुनिक Certbot लेआउट और लेगेसी निर्देशिका संरचनाओं, दोनों का समर्थन करना

## 2. मुख्य विशेषताएँ

### 2.1 एकीकृत PEM संयोजन
- **अटॉमिक राइट**: संयोजन के दौरान फ़ाइल अखंडता सुनिश्चित करने के लिए अस्थायी बफ़र का उपयोग करता है
- **न्यूलाइन सामान्यीकरण**: कुंजी और चेन घटकों के बीच उचित पृथक्करण की गारंटी
- **स्वतः खोज**: लेगेसी और आधुनिक Certbot लेआउट का बुद्धिमान स्कैनिंग

### 2.2 उन्नत क्रिप्टोग्राफ़िक सत्यापन
- **मॉड्युलस सत्यापन**: एकीकरण से पहले निजी कुंजियों का प्रमाणपत्रों के विरुद्ध गहन सत्यापन
- **कुंजी अखंडता**: मॉड्युलस निकालने और तुलना के लिए बहु-इंजन समर्थन (RSA/EC)
- **PFX मिलान**: v2.9.0 PKCS#12 निर्माण के लिए मिलान करने वाले कुंजी/प्रमाणपत्र जोड़ों की स्वतः खोज प्रस्तुत करता है

### 2.3 व्यापक लेआउट समर्थन
- **Certbot नेटिव**: `/etc/letsencrypt/live` संरचनाओं का नेटिव प्रसंस्करण
- **लेगेसी समर्थन**: `leX.crt` और `leX.key` नामकरण परंपराओं का समर्थन
- **TLD फ़िल्टरिंग**: टॉप-लेवल डोमेन के आधार पर अनुकूलन योग्य डोमेन प्रसंस्करण (डिफ़ॉल्ट: .ru, .com)

### 2.4 एंटरप्राइज़ परिनियोजन विशेषताएँ
- **ड्राई-रन मोड**: फ़ाइलसिस्टम में कोई परिवर्तन किए बिना इनपुट और आउटपुट पथों का पूर्ण सत्यापन
- **सुरक्षित अनुमतियाँ**: निजी कुंजियों और PFX फ़ाइलों पर 0600 अनुमतियों का स्वचालित अनुप्रयोग
- **लॉगिंग आर्किटेक्चर**: टाइमस्टैम्प के साथ बहु-स्तरीय लॉगिंग (DEBUG, INFO, WARN, ERROR)

## 3. सिस्टम आवश्यकताएँ

### 3.1 न्यूनतम आवश्यकताएँ
- **OS**: Linux (कोई भी आधुनिक वितरण), macOS, या WSL
- **शेल**: Bash 4.0 या उससे नया
- **उपयोगिताएँ**: `openssl`, `grep`, `awk`, `date`
- **अनुमतियाँ**: स्रोत प्रमाणपत्रों तक पढ़ने की पहुँच; आउटपुट निर्देशिकाओं तक लिखने की पहुँच

### 3.2 अनुशंसित कॉन्फ़िगरेशन
- **OpenSSL**: 1.1.1+ (आधुनिक ECC और friendly name विशेषताओं का समर्थन करता है)
- **फ़ाइलसिस्टम**: मानक Linux/Unix अनुमति मॉडल समर्थित
- **निर्भरताएँ**: PFX निर्माण और गहन कुंजी सत्यापन के लिए पूरा `openssl` टूलकिट

## 4. त्वरित शुरुआत मार्गदर्शिका

### 4.1 3 चरणों में परिनियोजन

**चरण 1: स्क्रिप्ट डाउनलोड करें**
```bash
wget https://raw.githubusercontent.com/paulmann/cert-unifier/main/cert-unifier.sh
chmod +x cert-unifier.sh
```

**चरण 2: मूल एकीकरण**
```bash
./cert-unifier.sh /var/www/httpd-cert
```

**चरण 3: उन्नत PFX निर्माण**
```bash
./cert-unifier.sh --pfx --pfx-password "your_password" /etc/letsencrypt/live
```

## 5. इंस्टॉलेशन और सेटअप

### 5.1 मैनुअल इंस्टॉलेशन
1. स्क्रिप्ट को सिस्टम PATH निर्देशिका में ले जाएँ (उदा. `/usr/local/bin`)
2. सुनिश्चित करें कि निर्भरताएँ पूरी हों: `apt install openssl grep awk`
3. यदि आवश्यक हो तो वातावरण चर कॉन्फ़िगर करें:
   - `ALLOWEDTLDS="ru com org"`
   - `LOGLEVEL="INFO"`

### 5.2 स्वचालित CI/CD सेटअप
कॉर्पोरेट वातावरण में GitLab CI या GitHub Actions के माध्यम से एकीकृत करें:
```yaml
- name: Unify Certificates
  run: |
    export ALLOWEDTLDS="com net"
    ./cert-unifier.sh --no-key-validation --output-dir ./dist /certs/source
```

## 6. आर्किटेक्चर और घटक

### 6.1 तर्क प्रवाह
1. **वातावरण जाँच**: OpenSSL संस्करण और निर्भरताओं का सत्यापन
2. **निर्देशिका स्कैनिंग**: लक्ष्य रूट में पुनरावृत्ति, लेआउट की पहचान
3. **सत्यापन**: मॉड्युलस निकालना; कुंजी-प्रमाणपत्र जोड़ों की तुलना
4. **संयोजन**: Concat(key, chain) -> .pem में अटॉमिक लेखन
5. **PFX निर्माण** (वैकल्पिक): PEM बंडल को PKCS#12 में बदलना

## 7. उपयोग के उदाहरण

```bash
# Dry run with verbose debugging
./cert-unifier.sh --dry-run --verbose /etc/letsencrypt/live

# Process all domains (no TLD filtering)
./cert-unifier.sh --no-tld-filter /var/www/certs

# Generate PFX files and skip mismatches
./cert-unifier.sh --pfx --skip-pfx-on-mismatch /opt/certs

# Override output directory
./cert-unifier.sh -o /tmp/unified_certs /var/www/certs
```

## 8. पैरामीटर संदर्भ

| विकल्प | विवरण | डिफ़ॉल्ट |
| :--- | :--- | :--- |
| `-d, --dry-run` | फ़ाइलें लिखे बिना सत्यापन | `false` |
| `-v, --verbose` | DEBUG स्तर की लॉगिंग सक्षम करें | `false` |
| `-t, --tlds` | अनुमत TLD की सूची | `ru com` |
| `-o, --output-dir` | आउटपुट पथ ओवरराइड करें | इनपुट निर्देशिका |
| `--no-tld-filter` | सभी डोमेन संसाधित करें | `false` |
| `--pfx` | PKCS12 फ़ाइलें बनाएँ | `false` |
| `--pfx-password` | PFX पासवर्ड सेट करें | खाली |

## 9. तकनीकी विचार

### 9.1 OpenSSL एकीकरण
स्क्रिप्ट रनटाइम पर OpenSSL संस्करण की क्षमताओं का पता लगाती है। OpenSSL 1.1.x और 3.x के लिए PFX `friendlyname` समर्थन स्वतः सक्षम होता है, जो Windows Certificate Manager में बेहतर UI एकीकरण सुनिश्चित करता है।

### 9.2 अटॉमिक राइट तंत्र
इस रेस कंडीशन को रोकने के लिए कि वेब सर्वर आधी लिखी गई प्रमाणपत्र फ़ाइल पढ़ ले, **Cert Unifier** `*.pem.new` में लिखता है और सफल सत्यापन पर अटॉमिक मूव/रीनेम करता है।
